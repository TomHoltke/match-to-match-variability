# Match-to-match variability of physical-demand metrics in professional football

Reproducible code and data for the manuscript on **within-player,
match-to-match variability (coefficient of variation, CV%)** of optical-tracking
physical-demand metrics, and how that variability differs between playing
positions.

> **Status:** the associated manuscript is **not yet published**. This repository
> is shared to allow review and reproduction of the analysis.

The pipeline starts from a shared player–match feature table and reproduces
**every table and figure in the manuscript** with two short commands.

---

## 1. What the analysis does

For each eligible player we summarise a season of matches into a per-player
mean, SD and **coefficient of variation (CV%)** for 19 physical-demand metrics
(running volume, change of direction, acceleration/deceleration, sprint
characteristics). Linear mixed-effects models and Tukey post-hoc contrasts then
test whether match-to-match variability differs by playing position
(central midfielder = reference).

The two commands below reproduce, one-to-one, the results reported in the
manuscript:

| Output | File | Where in manuscript |
|--------|------|---------------------|
| **Table 1** | `results/manuscript/Table1.xlsx` | Main text |
| **Figure 1** | `results/manuscript/Figure1_forest_position_vs_CM.png` | Main text |
| **Table S1** | `results/manuscript/TableS1.xlsx` | Supplement |
| **Table S2** | `results/manuscript/TableS2.xlsx` | Supplement |
| **Table S3** | `results/manuscript/TableS3.xlsx` | Supplement |

A formatted Word file containing all of the above
(`results/manuscript/Manuscript_tables_and_figure.docx`) is also written.

## 3. Installation

Requires **Python 3.10+**. From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` installs everything the analysis needs:

| Package | Used for |
|---------|----------|
| `pandas`, `numpy` | data handling |
| `openpyxl` | reading/writing the `.xlsx` files |
| `scipy`, `statsmodels` | linear mixed-effects models, Tukey HSD, likelihood-ratio tests |
| `matplotlib`, `seaborn` | Figure 1 |
| `python-docx` | the formatted Word document |

(Only needed if you want to inspect/re-run the reference feature-extraction code
in `src/features/`: `pyarrow` and `databallpy` — commented out at the bottom of
`requirements.txt`. They are not required to reproduce any result.)

## 4. Reproduce the manuscript results

Run the two steps in order, from the repository root:

```bash
python scripts/01_clean_and_summarise.py     # data/ -> cleaned table + player-season summary
python scripts/02_manuscript_results.py      # -> results/manuscript/ (Table 1, S1–S3, Figure 1)
```

| Step | Reads | Writes |
|------|-------|--------|
| 1 | `data/match_player_features.xlsx` | `data/match_player_features_clean.xlsx`, `data/player_season_summary[_no_gk].xlsx` |
| 2 | `data/player_season_summary.xlsx` | `results/manuscript/` — Table 1, Tables S1–S3 (`.xlsx`), Figure 1 (`.png`), and the combined Word document |

Both steps are deterministic: re-running them regenerates identical files. The
pre-generated outputs are committed for convenience, so you can inspect the
results without running anything.

### How to read the code, step by step

1. **`src/config.py`** — start here. Defines all file paths and the two
   inclusion thresholds (`MIN_MATCHES = 17`, `MIN_MINUTES = 60`) and the
   position grouping. Nothing here needs editing to run the pipeline.
2. **`src/preprocess/cleaning.py`** (called by step 1) —
   `clean_player_selection()` keeps only players with ≥ 17 matches of ≥ 60 min;
   `build_player_summary()` aggregates each player's matches into mean, SD and
   CV% for every metric and assigns a primary position group.
3. **`src/analysis/manuscript_results.py`** (called by step 2) — fits the three
   linear mixed-effects models (Table S2), computes the Tukey contrasts that
   drive both Table S3 and Figure 1 from one calculation, and assembles Table 1
   and Table S1. The `METRICS` list at the top maps each raw column to its
   table/figure label and is the single place metrics are defined.

## 5. The shared data

`data/match_player_features.xlsx` — one row per player per match.

**Identifier columns**

| Column | Meaning |
|--------|---------|
| `MD` | Match round (1–34) |
| `team_side` | `home` / `away` within the fixture |
| `team_id` | Club code (`T01`…`T18`) |
| `player_id` | Player code (`P001`…) |
| `shirt_num` | Shirt number in that match |
| `starter` | Whether the player started |
| `position_specific` | Detailed playing position label |
| `column_id` | Tracking-side identifier (`home_<n>` / `away_<n>`) |
| `playing_duration` | Minutes played (capped at 105) |

**Feature columns** (raw value and, where applicable, a `_per_90` version):
covered-distance speed zones (`total_distance`, `walking/jogging/running/`
`high_speed_running/sprinting_distance`), change of direction (`CoD_low/medium/`
`high/total`), acceleration/deceleration counts, distances and magnitudes
(`n_acc_3`, `n_dec_3`, `dist_acc_3_m`, `n_acc_SP`, `mean_acc_magnitude_ms2`,
`peak_acc_ms2`, …), and sprint characteristics (`n_sprints`, `sprint_distance_m`,
`mean_sprint_dist_m`, `mean_sprint_duration_s`, `mean/max/peak_speed_ms`). Metric
thresholds are documented in the docstrings of the modules in `src/features/`.

### Privacy

This dataset does not contain any identifying information about players, clubs,
the competition, or the season. Direct identifiers were removed and clubs and
players are referred to only by neutral codes (`team_id`, `player_id`). No
information that could re-identify any individual or club is included anywhere
in this repository.
